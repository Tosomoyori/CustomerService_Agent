# 三语智能客服 Agent（跨境通信业务）

面向跨境通信业务场景的三语智能客服 Agent：**C 端**覆盖漫游/大湾区计划咨询、套餐推荐、投诉工单与转人工；**B 端**提供企业跨境组网方案顾问（IEPL/IPLC/SD-WAN/MPLS VPN 等）与商机留资。系统以「**三语服务、资费防幻觉、隐私合规**」为硬性产品约束，配套三语评测集与护栏自检，Mock 模式下整条链路离线可跑、评测可复现。

> 业务背景取材于香港跨境通信运营商的真实业务形态（漫游/大湾区计划/企业专线），项目中不出现具体公司名，示例数据为业务结构演示。

## 1. 产品定义与设计约束

香港电信客服场景的特殊性在于：用户以粤语/港式繁体提问为主，资费数字是监管与投诉的高危区，个人资料处理受香港《个人资料（私隐）条例》（PDPO）约束。据此确立四条产品级硬约束：

| 约束 | 含义 | 落地机制 |
|---|---|---|
| 三语一致 | 粤语（zh-HK）/普通话（zh-CN）/英语（en）识别、理解与回复全链路一致 | 规则识别 + 归一化检索（见 §3）；每条回复按识别语言出三语模板 |
| 金额防幻觉 | 资费/按金/价格必须来自工具查询，禁止模型生成 | 结构化资费库 + `validate_amounts` 溯源校验，越界即回退确定性模板（见 §6） |
| 检索可溯源 | 知识问答必须给出知识库出处，查不到如实说 | 抽取式回答强制带「（来源：doc · section）」；低分命中转热线/人工 |
| 隐私最小化 | PII 只脱敏入库，公开热线不受影响 | `mask_pii`（电话/HKID/邮箱）+ 公开号码白名单，会话日志与落库均为脱敏态 |

业务数据（套餐、漫游包、企业方案、覆盖）为主流运营商公开业务形态的演示子集，存于 `data/*.json`，生产环境应替换为官方接口。

## 3. 三语处理：归一化的两个坑

**语言识别**（纯规则，36 例评测 100%）：无 CJK → en；含粤语标记字（唔/嘅/咗/喺/冇…）→ zh-HK；含繁体字 → zh-HK（繁体默认香港用户）；其余 → zh-CN。

**检索归一化**必须先做粤语词归一化、再做通用繁→简转换，顺序不能反：

- 「係」若先走繁→简会变成「系统」的「系」，污染检索词——粤语归一化要先行；
- 繁→简映射表**不能收录简繁同形字**（如「通」）：曾因表内含「通→通」恒等映射，简体「开通」被误判为繁体，语言识别连错 3 例。修复后映射表仅收录真正的异体字对。

归一化结果同时服务于：意图路由关键词匹配、BM25 检索、实体抽取——一份归一化，三处受益。

## 4. 意图路由与多轮会话

7 类意图：漫游咨询 / 套餐推荐 / 企业方案 / 知识问答 / 投诉工单 / 转人工 / 闲聊。

- **路由策略**：转人工、投诉工单两类安全关键意图**硬优先**（分数 >0 即命中，绝不挤占）；其余意图按加权正则得分取最高，平手按优先序裁决。36 例三语意图评测 100%，规则路由，Mock 模式零 LLM 调用。
- **会话状态驱动覆写**：多轮流程（企业留资、工单登记）未完结时，下一轮即使用户只发一个电话号码（会被误路由为闲聊），也强制延续原流程；「转人工」永远可退出当前流程。
- **子路由**：漫游意图下「eSIM 怎么开通 / 按金多少钱」这类不带目的地的流程类问题，转入知识库检索而非死问目的地。

## 5. 轻量 RAG：结构化切片 + BM25

- **切片**：按 Markdown 标题层级结构化切分（`# / ##`），≤400 字符，超长按句聚合，保留「文档 · 小节」坐标。
- **检索**：纯 Python BM25（k1=1.5, b=0.75），token = CJK 一元+二元 + ASCII 词元；**小节标题 token 双计**——产品名常只出现在标题、正文用代称，单计导致 Hit@1 漏召。
- **回答**：抽取式——按命中句序取句拼装，首命中取 2 句保证关键细节（按金、热线）不丢，强制附来源标注。检索评测 18 例：Hit@1 94.4%，Hit@3 100%，MRR 0.907。

不引入向量库与 Embedding 依赖：知识库仅 6 篇、检索语料小，BM25 在此量级召回质量足够且零部署成本；接口已按 `search_kb(query, top_k)` 抽象，后续可平滑替换为向量混合检索。

## 6. 护栏：资费溯源与隐私合规

**金额溯源**：`extract_amounts` 以多形态正则（`$128`、`HK$98.5`、`300 港元`、`$30蚊`）抽取回复中的全部金额，与工具/知识库来源文本中的合法金额集合比对，越界金额即判定幻觉——Mock 模式下模板生成本就只引用工具结果；真实模式下 LLM 话术越界时**整体回退确定性模板**，宁可话术朴素也不出错数。

**PII 脱敏**：香港手机号保留前 3 后 2（`912****67`）、内地手机号保留前 3 后 2（`136****78`）、HKID 保留首字母+检查位、邮箱保留首 1 字符；客服热线 `2122 1188` 等公开号码进白名单不脱敏。工单/线索落库与会话日志均为脱敏态。

**免责声明**：含金额的回复统一附加「以官方渠道为准」提示，且幂等不重复。

## 8. 快速开始

```bash
cd CustomerService_Agent
uv sync --extra dev            # 安装依赖（含 pytest/httpx/ruff）
uv run python -m app.server    # 启动 Mock 模式（无 API key 自动 Mock）
# 打开 http://127.0.0.1:8000 —— 三语聊天页，含快捷回复与推理链路 trace
```

**真实模式**（LLM 组织话术）：复制 `.env.example` 为 `.env`，配置 OpenAI 兼容接口（DeepSeek/Qwen 等均可）：

```
APP_LLM_BASE_URL=https://api.deepseek.com/v1
APP_LLM_API_KEY=sk-xxx
APP_LLM_MODEL=deepseek-chat
APP_MOCK=0
```

真实模式下 LLM 只在确定性工具结果上组织话术，金额越界自动回退模板（§6）。全量环境变量见 `.env.example`。

## 9. 关键设计决策

| 决策 | 备选 | 理由 |
|---|---|---|
| 规则路由为主，LLM 仅兜底 | 纯 LLM 分类 | 意图集合小且封闭；规则零延迟、可解释、离线可测；LLM 只在规则 0 分时兜底 |
| BM25 而非向量检索 | Embedding + 向量库 | 6 篇知识库量级下 BM25 足够且零依赖；接口抽象保留混合检索升级路径 |
| 抽取式回答而非生成式 | LLM 摘要生成 | 知识问答的底线是「不编造」；抽取 + 溯源在 Mock 模式同样成立 |
| 金额越界整体回退模板 | 只删错误数字 | 局部删除可能留下语义残缺；确定性模板永远自洽 |
| 会话状态覆写路由 | 每轮重新路由 | 「91234567」单发会被误判闲聊，多轮流程在关键槽位上不容路由抖动 |
| Mock/Live 双模式 | 仅 Live | 演示与评测不依赖 API key，clone 即跑；LLM 边界收敛在 compose 一层 |

## 10. 已知局限

- **示例数据**：资费/方案/覆盖为主流运营商公开业务形态整理的演示数据，生产需接官方接口并建立更新机制。
- **知识库语言**：知识库以简体中文书写，回复按用户语言出模板；繁体知识库版本未做（检索靠归一化桥接）。
- **检索失败例**：Hit@1 94.4% 的失败例为跨文档同义改写（正文用代称），Hit@3 已兜住；可加同义词典或向量召回进一步优化。
- **LLM judge 未做**：真实模式下的话术质量（语气、精炼度）暂无自动化评测，仅靠金额溯源护栏兜底。
- **单实例会话**：Session 存进程内存，多副本部署需外置（Redis）；SQLite 适用于演示级写入负载。
